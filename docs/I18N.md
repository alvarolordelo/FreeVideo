# Frontend internationalization (incremental migration)

FreeVideo historically embeds pairs of English and Chinese strings directly in
JavaScript. This change proposes a dependency-free catalog architecture that
keeps those existing translations working during migration.

## Locale selection
Use Settings > Appearance > Interface language, or the existing
`freevideo_lang` query parameter: `en`, `zh` or `pt-BR`. The explicit
selection takes priority over the browser locale. Unsupported locales fall back
to English. Without the optional Task Manager extension, changing the native
setting reloads the UI using FreeVideo's original mechanism (it does not
restart the server). With the Task Manager extension installed, Settings and
the command palette request the shared reactive locale instead and do not
reload the page. The extension's current-tab selection takes precedence until
the next independent browser tab or an explicit fresh launch.

## Adding UI text

1. Add a stable, contextual key to `web/locales/en.json`, `zh.json` and
   `pt-BR.json`. Keep the same keys across the catalogs.
2. Import `translateKey` from `web/i18n.js`. For example:
   ```js
   import { translateKey } from './i18n.js';
   const label = translateKey('ui.generate_video');
   const eta = translateKey('progress.estimate_minutes', undefined, {minutes: 18});
   ```
3. Run `node scripts/build_locales.mjs` to regenerate the bundled ES module.
   The generated module is checked in to avoid runtime JSON requests or
   dependency on import attributes in older browsers.
4. Run `node scripts/build_locales.mjs --check` and
   `node --test scripts/test_i18n.mjs scripts/test_freevideo_entry.mjs`.

Existing bilingual calls use the transitional `translatePair(en, zh, chinese)`
adapter. It preserves existing English/Chinese wording and uses known catalog
entries for Portuguese, falling back to English for untranslated strings.
New code should use stable keys instead. Keep labels separate from protocol
identifiers, prompts, model names, persisted settings, and workflow data.

## Scope and limits

This unified contribution centralizes locale selection and translation helpers,
migrates view navigation and primary video generation labels to keys, and
provides an initial Brazilian Portuguese catalog. Settings and common controls
can use the legacy bridge as their strings are migrated. Long tutorial and
release content, specialized editor controls, messages and more complex
pluralization still need dedicated migration and native-speaker review. This is
not a claim of complete Portuguese coverage. The optional Task Manager
extension is included in this unified branch; it supplies a reversible overlay
for known native strings and hosts the reactive language bridge. Without it,
the catalog API and reload fallback remain usable independently.

Browser acceptance testing of all locales, narrow layouts and live generation
continues to be required before upstream merge. Development used AI assistance.
